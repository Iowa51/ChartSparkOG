# FIX_INVITATION_URL_ROUTING.md

## Task

Update ChartSparkOG so all invitation URLs point at `/accept-invitation` (the route CC recently built in commit `21997aa`) instead of the legacy `/auth/accept-invite` path.

Currently, invitation links generated by the admin UI and the email template use `/auth/accept-invite`, which redirects to `/login` — breaking the invitation flow for any real user.

Read `CLAUDE.md` first for engineering standards. All work must conform to those standards.

**IN scope:**
- Find every place in the codebase that generates an invitation URL using `/auth/accept-invite`
- Update each one to use `/accept-invitation` (no trailing slash, `?token=` query parameter)
- Add a server-side redirect from `/auth/accept-invite?token=X` to `/accept-invitation?token=X` for backward compatibility with invitation emails already in users' inboxes

**OUT of scope — do NOT do:**

- Modify unrelated auth flows (`/login`, `/register`, `/forgot-password`)

- Add new dependencies or env vars

If you discover something that seems needed outside scope, STOP and ask.

## Step 3 — Add backward-compatibility redirect

Users have existing invitation emails in their inboxes with the OLD `/auth/accept-invite` URL. Those must continue to work after this fix.

Add a server-side redirect in Next.js so that `/auth/accept-invite?token=X` (GET) responds with a 308 Permanent Redirect to `/accept-invitation?token=X` — preserving the token query parameter.

Preferred implementation:
- Use Next.js `redirects()` config in `next.config.js` or `next.config.mjs`
- Example pattern:
  ```js
  async redirects() {
    return [
      {
        source: '/auth/accept-invite',
        destination: '/accept-invitation',
        permanent: true,
      },
    ];
  }
  ```
- Next.js automatically preserves query parameters on redirect by default — verify this is true for your Next.js version. If it does not, include `has: [{ type: 'query', key: 'token' }]` and the appropriate destination template.

Alternative if `redirects()` doesn't work for the existing project structure: add middleware at `src/middleware.ts` that rewrites `/auth/accept-invite` → `/accept-invitation`, again preserving the token.

Do NOT put the redirect logic inside the old route as a component-level client-side redirect. The redirect must happen server-side before any authentication middleware runs, otherwise the legacy URL will still get caught by the auth redirect and bounce to /login.

**Test the redirect before committing:**
- Locally run `npm run build` and `npm run start`
- Visit `http://localhost:3000/auth/accept-invite?token=TEST` — should 308 redirect to `/accept-invitation?token=TEST`
- Confirm the token query parameter is preserved in the final URL
