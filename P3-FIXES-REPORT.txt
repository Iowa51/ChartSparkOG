P3-CRIT-1  portal_submit_intake concurrency-safe                        [FIXED]
  Migration: CREATE OR REPLACE portal_submit_intake (re-derived verbatim) adds:
    1. SELECT ... FOR UPDATE on the parent submission BEFORE the idempotency
       check -> serializes concurrent patient_portal submits (the loser blocks,
       re-reads the claimed sentinel, returns already_submitted:true).
    2. Conditional atomic claim: UPDATE ... SET materialized_at=NOW()
       WHERE materialized_at IS NULL (row-count checked) BEFORE any child insert
       -> structural single-materialization backstop. Whole call is one txn: a
       later RAISE rolls back the claim too.
  Test (reconciliation.test.ts): "two concurrent patient_portal submits
    materialize exactly once (CRIT-1)" — two REAL patient_portal connections;
    exactly one already_submitted:false, one :true; 2 problems (not 4).

P3-CRIT-2  sign-readiness gate + full-disposition snapshot              [FIXED]
  Migration: CREATE OR REPLACE enforce_intake_submission_state (re-derived
    verbatim from ...150000 — SM-1/SM-2/created_by-immutability preserved) adds:
    a. provider_review requires submitted_at IS NOT NULL.
    b. reconciled/signed rejected while any first-class row is unresolved
       (unresolved = rejected=false AND (reconciled=false OR needs_coding=true)).
       OPERATOR POLICY: sign blocked until every problem/medication/allergy is
       rejected OR (reconciled AND NOT needs_coding).
    c. signed_snapshot captures ALL first-class rows via to_jsonb(row) — accepted
       AND rejected, each carrying its disposition flags (disposition, not omission).
  App: status route mirrors (a)/(b) for precise 409s (assertReconcileReady in
    src/lib/reconcile/data.ts). buildIntakeNoteDraft excludes rejected rows so the
    drafted clinical note shows only the accepted picture.
  Tests (both layers):
    - DB: provider_review-requires-submitted_at; unresolved -> reconciled RAISEs;
      snapshot records all first-class rows with disposition (accepted + rejected).
    - Route (status/route.test.ts): unresolved reconciled/signed -> 409;
      provider_review unsubmitted -> 409; fully-resolved sign -> 200 + note draft.
